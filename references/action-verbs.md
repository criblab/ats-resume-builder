# Action Verbs

Use an owned verb that describes what you actually did. One verb per bullet. Vary them across the page.

## Engineering and delivery

| Verb | Use when you... |
| :--- | :--- |
| Architected | designed the structure and trade-offs of a system |
| Built | implemented something from scratch |
| Designed | owned the design of an API, schema, or workflow |
| Developed | wrote a feature or service (use sparingly) |
| Engineered | solved a non-trivial technical problem |
| Implemented | delivered a defined design |
| Introduced | brought a new practice, tool, or system |
| Migrated | moved data, traffic, or platforms |
| Modernized | replaced legacy components |
| Refactored | restructured code without changing behavior |
| Replatformed | moved to a different runtime or vendor |
| Shipped | delivered to production |

## Impact

| Verb | Use when you... |
| :--- | :--- |
| Reduced | cut cost, latency, errors, or time |
| Increased | raised throughput, conversion, or adoption |

| Accelerated | made a process faster |
| Scaled | handled more traffic, data, or users |
| Stabilized | reduced incidents or flakiness |

## Notes

- Do not start every bullet with the same verb. Scan the first words of each bullet; if three match, rewrite two.
- Prefer concrete verbs over abstractions ("Cut" over "Optimized", "Shipped" over "Delivered").
- Past tense for previous roles, present tense for the current role, both acceptable in a resume as long as it is consistent within a role.
- Avoid "Spearheaded" unless you truly led the initiative; recruiters read it as inflated.
- Avoid "Leveraged" and "Utilized". They add syllables, not information.
